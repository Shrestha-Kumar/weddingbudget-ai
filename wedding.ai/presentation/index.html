The Problem

India's luxury weddings operate inside a financial black box.

Wedding budget planning in India is an art passed down through experience. Planners rely on gut feel and past project memory to give clients estimates. There is no data-driven tool that can intelligently estimate a wedding budget based on structured inputs.

The Gap: A single destination wedding spans ₹50 Lakhs to ₹10 Crores, yet no intelligent platform bridges the gap between creative mood boards and hard financial reality.

🎭

Décor is 100% Subjective

A Mehendi setup vs. Reception stage can differ by 10x in cost. No tool quantifies visual aesthetics into budgets.

🚐

Logistics are Guesswork

Fleet sizing, per-head F&B, driver allowances — planners calculate these from memory, introducing massive variance.

📊

Zero Post-Booking Tracking

After vendor contracts are signed, there is no system to track actuals vs. estimates in real-time.

Machine Learning Architecture

ONNX Runtime — Production-grade inference without GPU.

Inference Pipeline

INPUT → Download Image (httpx async)
│
PREP → Resize 224×224, ImageNet Normalize
│     mean=[0.485, 0.456, 0.406]
│     std=[0.229, 0.224, 0.225]
│
ONNX → CPUExecutionProvider Inference
│     Input: [1, 3, 224, 224] float32
│     Output: [low, mid, high, conf]
│
CV → Grad-CAM via OpenCV Saliency
│     Canny → Dilate → JET Colormap
│
OUT → JSON { costs, confidence, heatmap }

Why ONNX over PyTorch?

Container Size ~2.5 GB ~200 MB
Cold Start 15-30s 2-3s
GPU Required Yes No
Free Hosting ❌ ✅

The ONNX format achieves 2-4x faster CPU inference than native PyTorch, enabling sub-second predictions on free-tier cloud hosting without any GPU dependency.

Design Decisions

Why Decoupled?

Vercel serverless has a 250MB limit and 60s timeout. Our Python ML stack (ONNX + OpenCV) exceeds 500MB. The backend must be containerized.

Why Hugging Face over Render?

Render free tier sleeps after 15 minutes of inactivity, causing 60-second cold starts. HF Spaces stays always-on during demo evaluations.

Security

All secrets (SUPABASE_URL, SUPABASE_KEY) injected via platform-native secret managers. No credentials in source code. Client data stored securely.
